# A usable end-to-end pipeline — design

Date: 2026-09-28. Status: approved in conversation, section by section; this file records it.

## 1. Intent

A new user should be able to take LFA from nothing to an adapted model by following one page:
build a p(h) artifact from the model's own text, prepare their domain documents (optionally with
the model-written question-and-answer supplement), train, evaluate, fuse, and go on to a second
domain. The package should stop depending on published artifacts entirely, should never lose hours
of generation to a late failure, and its documentation should be written for that user rather than
for a reader of the private research record. Documents that existed only to build the companion
go.

What the owner said, in order: the pipeline should use self-generated data for the artifact; data
preparation should include the option to supplement domain data with self-generated supplements;
lingering construction documents should be found; the published `qwen3-0.6b-gmm1543k-int8`
artifact is **not** included — users create their own by self-generation and can reuse it once
they have it; reuse is automatic with `--rebuild` to opt out; no GPU tests in this pass — a
handoff document carries them to a later session.

### 1a. The supplement is framed as what it is

The supplement offered at data preparation is the existing self-written question-and-answer
supplement. Its measured effect is on whether the domain's knowledge can be reached when the model
is asked about it; it does not protect skills (a supplement written in a skill's mode left the
skill no better, measured on instruction following and reasoning, one model, one seed). Skill
retention under LFA is the anchor's job: with the anchor on, instruction following stayed at the
base model's level with or without the supplement. No user-facing text calls it a skill supplement
or says it protects skills. Rehearsal on model-written text is out of scope.

## 2. Code changes

### 2.1 No published artifacts

- Remove the artifact registry (`ARTIFACTS`), `lfa/artifact/fetch.py`, the `fetch-artifact`
  subcommand, `Workspace.init(artifact_id=...)`, the CLI's `--artifact-id`, and every code path
  that reads a registry entry (the registry-supplied base sample count for `extend`, the
  "registry id wins over a path" rule, `ArtifactNotPublished`). An artifact whose meta carries no
  `n_samples_total` makes `extend` refuse, and the message no longer mentions a registry.
- `lfa init --artifact` becomes **required**. It takes `self-generated` or a path to an artifact
  file. Omitting it is an argparse error whose help text names `self-generated` as the way to a
  first artifact. `Workspace.init(artifact=...)` loses its default the same way.
- The recipe's reference artifact becomes the self-generated one: `artifact:` and
  `calibrated_artifact:` in the bundled YAML become `self-generated`, and the YAML gains
  `self_generated_frame: {n_raw: 2500, n_chat: 0, max_new_tokens: 2048, max_samples: 600000,
  gmm_k: 32, pca_variance: 0.95}` — the frame the calibration claim was measured at.
  `calibrated_self_generated` is dropped as redundant (a recipe whose `calibrated_artifact` is
  `self-generated` is calibrated against it). The YAML's comment says, plainly, that λ was tuned
  against a real-text artifact (the 10:1 pretraining-to-instruction seed corpus, 1.54 M samples
  per site) and that an artifact fitted on the model's own text at this frame matched it at every
  λ tried and was at least as good at the recipe's λ — one model, one seed, one domain.
- `Recipe.warnings(rank, artifact_id, artifact_meta)` keeps its signature (a user's own recipe
  may still be calibrated against a named file, compared by id as today); for a recipe whose
  `calibrated_artifact` is `self-generated` it judges the artifact by its meta:
  - self-generated by this recipe's model at `self_generated_frame`: silent;
  - self-generated by this recipe's model at another frame: a note naming the fields that differ
    and saying λ was not calibrated there (a trial build is the common case);
  - self-generated by another model: the existing mismatch note;
  - real-text (`provenance` absent) or unknown: a note that the recipe's λ is calibrated against
    the self-generated artifact at its frame and this one is not that, so calibrate λ
    (`docs/adding-a-model.md`). Never a refusal.

### 2.2 The local artifact store and automatic reuse

- Location: `$LFA_ARTIFACT_STORE`, else `~/.cache/lfa/artifacts/`.
- An entry is a directory `<model-slug>-<writer_sha256[:12]>-<frame_sha256[:12]>/` holding
  `artifact.pt`, `corpus.jsonl` and its manifest, `entry.json`, and while a build is in
  progress `corpus.jsonl.partial` plus `corpus.jsonl.progress.json` (the durable writer names
  both after whatever corpus path it is given, so `build-artifact --out` gets the same). `frame_sha256` hashes the canonical JSON of the
  frame (the `SelfGenOptions` fields that shape the corpus and the fit: `n_raw`, `n_chat`,
  `max_new_tokens`, `seed`, `chat_seed`, the filters, `max_samples`, `gmm_k`, `pca_variance`,
  `reservoir_size`; not `batch_size`, `device` or `layer_group_size`, which change speed or the
  host-RAM plan but not the frame the docs describe).
- `lfa init --artifact self-generated` hashes the checkpoint, looks up the entry, and:
  - entry has `artifact.pt`: copy it in as `artifacts/v1.pt` (with the corpus and manifest
    beside it, as today), log `Reused the self-generated artifact built <date> from <store path>`;
  - entry has a complete corpus but no artifact (an earlier fit failed): fit, then copy in;
  - entry has a partial corpus: resume generation, fit, copy in;
  - no entry: build into the store, then copy in.
  `--rebuild` (and `Workspace.init(..., rebuild=True)`) moves any existing entry aside to
  `<entry>.replaced-<timestamp>/` before building; it never deletes a finished artifact silently.
- A build takes `<entry>/.lock` with an exclusive create; a second concurrent build of the same
  entry refuses with a message naming the lock and the other process's pid. A stale lock (pid not
  alive) is taken over with a warning.
- `lfa list-artifacts` lists the store: model id, frame summary (documents × tokens, K), built
  date, size, and path; an in-progress entry shows `n / N documents`.
- `lfa init --artifact <path>` reuses any file. Provenance and id come from the file's meta: a
  self-generated file records `artifact_provenance: self-generated` and
  `artifact_id: self-generated:<corpus_sha256[:12]>`, exactly as if it had been built at init.
  Any other file is recorded by the path the user passed (`artifact_id` = that path), no provenance.
- `lfa build-artifact --self-generated --out PATH` stays explicit (no store); it gains the same
  durability (2.3), with its partial corpus beside `--out`.

### 2.3 A durable self-generated build

- Generation appends each finished batch's surviving documents to `corpus.partial.jsonl` and
  rewrites `progress.json` (`batches_done`, `raw_done`, `chat_done`, `empties`, the frame hash)
  after each batch, via write-to-temp-then-rename. It logs `self-generated corpus: n/N documents
  (e empty)` per batch at INFO.
- Resume: when the progress file's frame hash matches, generation starts at the recorded batch
  of each share, with the batch size the build started with, and the same per-batch seed (`seed * 1_000_003 + batch_index`, unchanged), and the empties
  count carries over, so the degenerate-corpus limits apply to the whole build, not to the
  resumed tail. A mismatched frame hash refuses and names `--rebuild`.
- On completion the partial file is renamed to `corpus.jsonl`, the manifest written, and
  `progress.json` removed. The corpus hash is computed over the final file, so a resumed build's
  manifest is indistinguishable in form from an uninterrupted one's.
- The fit reads the completed corpus. A fit failure or interruption leaves the corpus in the
  store; `Workspace.init`'s failure cleanup removes only what it created inside the workspace.
- Ctrl-C during generation prints one line naming the store entry and saying the same command
  resumes.

### 2.4 Data preparation with the supplement

- `lfa prepare-supplement` takes either `--workspace` (unchanged: the writer is the workspace's
  current model, the file lands in the workspace's `supplements/`) or `--model ID` (new: no
  workspace; the file lands beside the corpus at `<corpus>.supplement/<corpus_hash[:12]>/
  supplement.jsonl` with its manifest). With `--model`, the train/held-out split comes from
  `--recipe` or the bundled recipe naming the model; neither is a refusal naming `--recipe`.
- `lfa prepare-domain ... --out DIR --supplement --model ID [--recipe] [--domain-description]`
  writes the corpus, then calls the same function. `--supplement` without `--model` is refused
  (exit 2) before anything is written.
- `train` looks for a matching supplement (corpus hash of the training side, writer hash,
  template hash, domain description — the existing key) first in the workspace's `supplements/`,
  then beside the corpus; if neither matches it writes one into the workspace, as today. So a
  supplement prepared with the base model is reused by stage 1, and a chain's stage 2 — whose
  entry model is the fused stage-1 model — writes its own.
- The manifest records the writer id and hash, so a user can see which model wrote a file.

### 2.5 Wording sweep in code

- Docstrings, comments, CLI `--help`, log and refusal messages, and the recipe YAML: the research
  claim ids (C12, C14, C15) and "the LFA record" / "the record" become plain statements of what
  was measured and at what scale. The five `mr-fusion` mentions (`lfa/selfgen/__init__.py`,
  `artifact_corpus.py`, `generate.py`, `supplement.py`, `lfa/corpus.py`) become "the research
  code" with no repository or script path.

## 4. Tests (fast tier, run in this pass)

- Resume: an injected `generate` interrupted after batch k, then resumed, produces a corpus file
  and manifest identical to an uninterrupted run; empties carry across the resume; a changed frame
  refuses.
- A fit that raises leaves the store's corpus in place; a second `init` fits without generating
  (the injected `generate` is not called).
- Store: match on checkpoint hash and frame; a frame change misses; `--rebuild` moves the entry
  aside; a held lock refuses; a stale lock is taken over.
- `init --artifact <path>` with a self-generated file records its provenance and id; a file with
  no meta records the path.
- `init` without `--artifact` is refused by argparse and the help names `self-generated`.
- `Recipe.warnings`: silent at the recorded frame, names the differing fields at a trial frame,
  notes a real-text artifact.
- `prepare-supplement --model` writes beside the corpus; `train` reuses it when the writer
  matches; a workspace whose current model differs writes its own.
- `prepare-domain --supplement` without `--model` is refused.
- No module imports `lfa.artifact.fetch`; `fetch-artifact` is gone from the CLI.
- The release test is rewritten: the `<org>` placeholder and registry-checksum checks go with the
  registry; a scan of every shipped file (package, docs, README, examples, recipe YAML) refuses
  `C1[0-9]` claim ids, `the LFA record`, `mr-fusion`, `gmm1543k` and `--artifact-id`, with
  `docs/verification.md` and `docs/superpowers/` exempt. It skips `.worktrees/`.

A GPU end-to-end test is written (marked `gpu`) and **not run** in this pass: `init --artifact
self-generated` at `--n-raw 60 --max-new-tokens 128` → `prepare-domain --supplement` → `train
--epochs 1` → `evaluate --n-windows 5` → `fuse`, then a second `init` that must reuse from the
store.
